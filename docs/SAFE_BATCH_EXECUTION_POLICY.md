# 547 户批量采集：稳态运行与自动止损策略

版本：1.0
输入：`lt-success-new3_去重复_文本对比.txt`
输入规模：547 条非空记录

## 0. 前提

仅处理已获授权的账号，并遵守目标网站服务条款、隐私和访问频率限制。本策略不是规避风控的方法，不允许隐藏自动化行为或绕过 CAPTCHA、2FA、Passkey。

## 1. 核心目标

```text
持续产生有效结果
不把技术错误扩散为账号失败
不混合批次
不覆盖历史证据
每批完成后再决定是否继续
```

## 2. 分批策略

不要一次启动 547 户。

固定分批：

```text
第1批：5户（校准批）
第2批：10户
第3批：20户
第4批：50户
第5批及以后：每批50户
```

只有连续两个批次达到通过门槛，才允许扩大到下一档。

如果出现熔断条件，回到上一档，不得继续扩大。

每批必须生成唯一：

```text
batch_id
input.sha256
results.json
screenshots/
evidence_manifest.json
output.xlsx
audit.json
run.log
```

## 3. 并发与频率

初始配置：

```text
Worker：1台
并发：1
账号之间间隔：8~15秒，使用固定配置，不随机规避风控
页面阶段之间按页面完成条件等待，不用固定短等待判断成功
```

校准批通过后：

```text
10户：最多2个并发
20户：最多3个并发
50户：最多4个并发
```

禁止直接使用：

```text
30线程/节点
120线程总并发
140线程总并发
```

并发提升只能在批次完成、验收通过、错误率稳定后进行。

## 4. 单账号流程

```text
领取账号
→ 建立独立 BrowserContext
→ 登录
→ 保存登录结果截图
→ 若登录成功，保留同一 Cookie/Context
→ 访问个人资料并截图
→ 访问订单列表并截图
→ 最多抓3笔订单详情并截图
→ 上传证据
→ 回报结果
→ 关闭 Context
```

规则：

```text
登录失败：不进入资料和订单
登录成功：必须继续资料和订单
资料没有：字段留空，profile_status=empty
资料访问失败：profile_status=failed
订单没有：orders_status=no_orders
订单访问失败：orders_status=failed
技术异常：technical_retryable 或 technical_final
最多订单：3
```

## 5. 状态分类，禁止误杀

### 账号证据状态

只有出现官方页面证据时使用：

```text
wrong_password
account_locked
two_factor
passkey
captcha
```

必须保存：

```text
官方页面文案
最终 URL
对应截图
```

### 技术状态

以下全部不能写成密码错误：

```text
页面超时
输入框未出现
密码框未出现
SSO跳转失败
代理连接失败
DNS/TCP失败
浏览器崩溃
Target closed
DOM解析失败
截图失败
上传失败
Master回报失败
```

分类为：

```text
technical_retryable
technical_final
```

## 6. 批次自动熔断

任一条件满足，立即停止当前批次并保留已完成结果：

```text
连续5户技术异常
连续3户同一代理异常
最近10户技术异常 >= 30%
最近10户密码错误 >= 95%，且没有对应官方错误截图
成功账号中资料失败 >= 20%
成功账号中订单失败 >= 20%
结果回报失败 >= 1户
截图缺失 >= 1户
JSON与Excel数量不一致
前端批次号与Worker批次号不一致
```

熔断后状态必须是：

```text
PARTIAL / STOPPED_FOR_REVIEW
```

不是：

```text
COMPLETED
```

## 7. 批次通过门槛

### 5户校准批

```text
5个结果全部回报
账号不重复
batch_id一致
技术异常与密码错误分开
登录成功账号均继续资料/订单
每户订单 <= 3
截图manifest完整
Excel可打开
Excel与JSON逐字段一致
```

### 10户批次

```text
以上全部满足
至少1个Worker有真实claim/report
没有连续技术异常
前端显示的total和processed与Master一致
```

### 20/50户批次

```text
连续两个批次无熔断
技术异常比例 < 20%
结果回报成功率100%
截图清单完整率100%
Excel订单行数与JSON一致
```

注意：密码错误比例高不自动判定系统错误，但每个密码错误必须有官方错误证据；没有证据就归入待复核/技术异常。

## 8. 每5分钟监控指标

只记录汇总，不输出账号、密码和个人信息：

```text
batch_id
总数
已处理
待处理
active
wrong_password（有官方证据）
two_factor/passkey/captcha
technical_retryable
technical_final
profile_empty
profile_failed
orders_no_orders
orders_failed
订单总数
截图数
最近一次成功时间
最近一次回报时间
```

必须同时监控：

```text
进度是否增长
最近回报时间是否更新
Worker心跳是否更新
失败分类是否突然变化
```

## 9. 任务暂停/恢复

### 可以自动继续

```text
正常完成
明确官方密码错误
明确2FA/Passkey/CAPTCHA
真实确认无订单
```

### 必须暂停复核

```text
技术超时
代理错误
页面结构异常
截图上传失败
Master回报失败
成功但资料为空且没有资料截图
订单列表为空但没有订单截图
```

恢复时：

```text
创建新attempt_id
保留旧attempt结果
不覆盖旧日志
不把旧技术失败改写成密码错误
```

## 10. 数据保存规则

每个批次独立目录：

```text
data/runs/<batch_id>/
```

禁止：

```text
写全局orders_cache
覆盖最近一次批次
跨批次合并截图
从旧Excel补字段
下载失败复制本地Excel冒充Web结果
```

## 11. 运行顺序

```text
1. 读取输入并只记录输入哈希
2. 切出5户校准批
3. 远程Worker低并发执行
4. 等待批次完成或熔断
5. 下载results/manifest/截图/Excel
6. 本地独立验收
7. 人工抽查少量截图
8. 通过后运行10户
9. 再运行20户
10. 再运行50户
11. 连续稳定后才继续50户批次
```

## 12. 运行报告固定格式

```text
批次：<batch_id>
输入：<数量>户 / <sha256>
执行节点：<worker_id列表>
并发：<数量>
处理：<完成>/<总数>
账号证据状态：...
技术异常：...
资料状态：...
订单状态：...
截图：<已生成>/<应生成>
Excel：通过/失败
独立验收：PASS/PARTIAL/FAIL/BLOCKED
熔断：是/否
下一步：继续当前档/退回上一档/暂停复核
```

禁止报告只写：

```text
全部成功
全部失败
运行正常
100%完成
```

## 13. 最低安全要求

```text
不在日志打印密码
不在报告打印密码
不把密码写入源码
不把密码写入普通JSON
不把Cookie写入报告
不把个人资料截图公开分享
```

输入文件属于敏感凭证文件，批次完成后应转入受保护目录并限制权限。
