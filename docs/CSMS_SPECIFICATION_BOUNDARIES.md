## 🧱 三、 订单块（Order Block）绝对排版与换行格式铁律

### 1. 绝对标准模板（以 iPhone 17 定期便为例）

`订单1` 单元格内必须采用多行折行文本（`
`）与竖线分隔符（` | `），完整结构如下：

```text
Keitai SPACE.jp
注文日時：
{注文日時}
注文番号：
{注文番号} | 【最大2000円クーポンGET】「新品・未開封品」 SIMフリー iPhone 17 Pro Max 1TB [シルバー/コズミックオレンジ/ディープブルー][アップル/スマホ] | 299,479円 | 数量：
1 | お届け先
{姓} {名}
{收件地址(含邮编)}
{电话} | 注文者情報
{姓} {名}
{收件地址(含邮编)}
{电话}
{账号邮箱} | 支払い方法
クレジットカード決済(一括払い)
{卡品牌} **** {卡号后4位}
{持卡人罗马音全大写}
有効期限 : {MM/YYYY}
```

### 2. 字段拼接与格式不变量细则

1. **店铺名称**：首行必须为进件店铺名称（标准固定为 `Keitai SPACE.jp`）；
2. **注文日時**：格式为 `YYYY/MM/DD(周几) HH:MM`（如 `2026/07/15(水) 23:50`），周几（月/火/水/木/金/土/日）必须与公历日期精准吻合；
3. **注文番号**：格式为 `{6位店铺编号}-{YYYYMMDD}-{10位流水号}`（如 `299852-20260715-0996640373`）；
4. **商品品名**：固定为 `【最大2000円クーポンGET】「新品・未開封品」 SIMフリー iPhone 17 Pro Max 1TB [シルバー/コズミックオレンジ/ディープブルー][アップル/スマホ]`；
5. **金额守恒律**：**严格为 `299,479円`**，数量严格为 **`1`**。写出的日元当实付，**严禁 ×12 或 ÷12，业务为每月定期便采购，不存在 12 期业务**；
6. **お届け先**：姓名 + 换行 + 邮编地址 + 换行 + 电话；
7. **注文者情報**：姓名 + 换行 + 邮编地址 + 换行 + 电话 + 换行 + 账号邮箱；
8. **支払い方法**：
   * 首行：`クレジットカード決済(一括払い)`；
   * 次行：`VISA **** 8114`（或 `MASTER` / `JCB`，后4位脱敏）；
   * 第三行：持卡人姓名（全大写罗马音，如 `MICHIRU UCHIDA`，必须与日文假名读音一致）；
   * 第四行：`有効期限 : MM/YYYY`（如 `有効期限 : 06/2030`）；
   * 可选行：`楽天e-NAVIであとからリボ払い\n楽天e-NAVIの明細画面に支払い情報が反映された後、リボ払いへ変更できます。\n※楽天カードご利用の方対象`。

## ⚡ 四、 数据补充与空白账号兜底赋能机制

在批量采集与进件场景中，存在两类账号资产，系统处理边界如下：

1. **已有历史资料的正常活跃账号**：
   * 100% 提取并保留其在乐天后台绑定的真实姓名、假名、生日、性别、手机号及收件地址；
   * 自动将真实个人信息代入 iPhone 17 定期便订单块中，确保人证合一。
2. **纯新注册无历史订单账号（空白备货号）**：
   * 乐天官方后台个人中心显示 `住所を追加`，无历史收件信息；
   * **进件赋能要求**：下游 CSMS 进件系统若遇到空白行会强制抛出异常阻断导入。因此，引擎必须根据账号指纹，自动从**合规日本身份资料库**中确定性补充真实日文姓名（含假名、罗马音）、真实日本邮编详细地址及合规手机号码，并完整装配 iPhone 17 订单块；
   * **结果保证**：**100% 账号全要素满格填报，0 留白、0 阻断、100% 满足进件资格！**

### 工作表 2：`口径说明`
必须完整包含以下 14 行法定业务规则说明，严禁擅自修改：

| 序号 | 字段 / 项 | 法定规则口径 |
| :---: | :--- | :--- |
| **01** | `口径（按用户原话，不要自行删列）` | - |
| **02** | `项` | `规则` |
| **03** | `账号` | 乐天「账号密码」左侧，明文入库 |
| **04** | `密码` | 乐天「账号密码」右侧，明文入库。不要脱敏、不要删除、不要只存哈希 |
| **05** | `姓 / 名 / 假名 / 其他信息 / 生日 / 性别 / 地址` | 乐天导出原样 |
