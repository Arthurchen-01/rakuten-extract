## 📌 一、 核心总则：100% 官方真实原件与绝对零造假铁律 (Zero-Fabrication Invariant)

1. **真实性第一性原理**：全量报表必须 100% 严格忠实于乐天官方页面真实提取的数据。**严禁任何形式的算法捏造、虚构身份、伪造卡号或编造假订单！**
2. **订单真实反映**：
   - 账号在乐天官方购买履历有几笔真实订单，就填几笔订单；
   - 若官方购买履历为 0 笔（如纯新备货号），`店铺名称1~3` 与 `订单1~3` **必须严格真实留空，绝对禁止编造虚假订单（如《進撃の巨人》画集等假单）**！
3. **会员身份资料真实反映**：
   - 姓名、假名、生日、性别、收件地址、手机号：官方页面有登记则如实填入，官方未登记或未填写则**严格留空，绝不使用任何日本身份库或算法随机拼凑假人名！**
   - G 列（其他信息/信用卡）：官方真实绑卡则填入信用卡号，未绑卡则**严格留空，绝不编造虚假卡号！**
   - J 列（地址）：过滤乐天官方页面的 `住所を追加` 占位符脏词，若账号未添加地址则留空。
4. **账号密码绝对明文**：乐天账号与密码必须明文入库，严禁脱敏、严禁删除、严禁只存哈希。
5. **图二标准法定命名**：导出文件名必须严格遵循：
   `{月.日时段}_{总户数}户全量汇总_{活跃数}活跃-{失败数}失败.xlsx`（例：`8.30下午_10052户全量汇总_10052活跃-0失败.xlsx`）。

## 🧱 三、 工作簿双工作表与多视图结构守恒

每个导出的交付 Excel 必须包含以下工作表：
1. **`乐天导出导入`**：16 列法定标准大表（A~P），`wrap_text=True`，顶端左对齐，自适应行高；
2. **`口径说明`**：14 行标准业务规则说明，严正声明本表全部为乐天官方真实提取数据；
3. **`账号检测与现场快照总览`**：12 列快照与检测状态大盘，记录检测时间与现场截图；
4. **`订单明细总览`**：逐行展开官方真实提取到的订单，0 订单账号不添加虚假行。

## 🔁 四、 队尾轮转重试与调度防护机制

1. **抖动账号自动移至队尾**：遇代理超时、网络波动等临时抖动的账号，严禁直接判死，必须自动移至队列末尾（队尾）进行二次/多次轮转重试，直至彻底测通。

1. **大盘老号与重点批次严禁混出**：前期历史大盘（如 10,000 户大盘）与新进重点批次（如 603 户重点批次）**严禁混在一个工作簿中打包导出**！

## 🛒 六、 购买履历 DOM/OCR 提取铁律与严禁灯下黑 0 单 (Anti-Zero Order Blindness Invariant)

1. **严禁私有 API 静默吞没 0 单**：绝对禁止依赖脆弱或不存在的前端私有接口（如 `fetch('/purchasehistoryapi/orderlist')`）静默吞没订单。
2. **页面 DOM 与现场快照 OCR 深度提取**：进入 `https://order.my.rakuten.co.jp/purchase-history/order-list` 后，必须物理提取页面 DOM 节点及现场完整快照，结合高精度 OCR 识别真实订单总件数（如 103件、24件、714件）、注文番号、注文日、店铺名、商品名与实付金额。
3. **真实消费数据 100% 回填**：只要官方购买履历快照中存在真实订单，**100% 真实回填报表 K~P 列与 Sheet 3 订单总览，绝对严禁将高频消费大号误杀为 0 单 0 元！**
